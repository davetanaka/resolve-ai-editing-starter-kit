# 11キットを育てる（あなた専属の編集マンにする）

このキットは完成品ではありません。**あなたのAIと一緒に育てる「芯**」です。

私（デイブ田中）の決まりも、最初からこうだったわけではありません。AIが組んだものを私が直し、その直しを決まりに書き足す。それを1本ずつ繰り返して、いまの形になりました（docs/09）。あなたも、ここから始めて、あなたのやり方に書き換えていってください。

---

## 育て方の回り方

```
使う（AIに頼む）
  ↓
あなたが直す（いつもどおりResolveで仕上げる）
  ↓
AIが「直した所」を見て、決まりに足す案を出す
  ↓
あなたがOKした案だけ、MY_RULES.mdに書き足す
  ↓
次から、AIが最初からそうしてくれる
```

コツは、**決まりを書くのはAI、決めるのはあなた**、と分けることです。あなたは「それでいい」「そこは違う」と答えるだけで、決まりが増えていきます。

---

## 頼み方

### 作業の終わりに（毎回）

```
今日の作業で、私が直した所を見てください。
AIが組んだタイムラインと、私が仕上げたタイムラインを比べて、
決まりに書き足すとよさそうなことを、3つまでに絞って案を出してください。
書き足すのは、私がOKと言ってからにしてください。
```

> 比べるには、AIが組んだタイムラインを消さずに残しておき、あなたは複製して仕上げます（AGENTS.mdの決まり）。

### 自分の書式を覚えさせる（最初に1回）

```
このプロジェクトのパワービン（または「テロップ」のビン）にある、
私のテロップのひな形と、オープニング・エンディングの素材を読んでください。
次から使えるように、MY_RULES.mdに書き足す案を出してください。
```

### 合わない決まりを直す・消す

```
docs/03-cut-rules.mdの「余韻は0.4秒」は、私には長すぎます。
私の好みは0.2秒です。MY_RULES.mdに、私の決まりとして書き足す案を出してください。
```

docs/ にある決まりは、私の好みです。合わないものは、docs/ を書き換えるのではなく、MY_RULES.mdに「私はこうする」と書けば、AIがそちらを優先します（キットを新しい版に入れ替えても、あなたの決まりが消えません）。

### 月に1回の見直し

```
MY_RULES.mdを読み直して、
重なっている決まり・古くなった決まり・最近使っていない決まりを一覧にしてください。
まとめ方の案を出してください（直すのは私のOKのあと）。
```

---

## 育てるときの決まり

- **書き足す前に、必ずあなたに見せる**。AIが勝手に決まりを増やすと、あなたの知らない決まりで動くようになります
- **理由も一緒に書く**。「なぜそうするか」が残っていると、あとで見直すときに迷いません（例：「切り口は0.2秒残す。0.4秒だと間延びして見えたため」）
- **フォルダごと保存しておく**。GitHubの自分のリポジトリにしておくと、いつ何を変えたかが残り、前の形にも戻せます
- AIが書いた便利なスクリプトも、このフォルダに保存させておくと、次から使い回せます（docs/10）
